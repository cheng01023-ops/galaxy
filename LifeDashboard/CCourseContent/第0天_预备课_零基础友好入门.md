## 一、编程到底是在做什么？

### 1.1 打个比方：编程 = 给电脑写"说明书"

电脑和人不一样，它**不会猜**。你让它做什么，就必须一步一步说清楚，
而且顺序不能错、细节不能少。哪怕漏掉一个步骤，它都会"卡住"或者给出错误结果。

比如让电脑"把 1 加到 100"，你不能只说"算一下 1 加到 100 等于几"，而要拆成它听得懂的步骤：

1. 准备一个盒子（变量），先放 0 进去
2. 拿数字 1，加进盒子
3. 拿数字 2，加进盒子
4. ……一直加到 100
5. 把盒子里最终的数字告诉用户

**编程（Programming）就是写这样一份"说明书"**。这份说明书用人类能读、电脑能执行的
语言写成，C 就是其中一种语言。

> 我们平时用的 App、网页、游戏，本质上都是"很多很多条这样的指令"的集合。

### 1.2 为什么学 C？

C 语言诞生于 1972 年，是**最经典、最有影响力**的编程语言之一：

- 离电脑底层很近，能直接操作**内存、地址、指针**，理解计算机真正怎么工作
- 操作系统（Windows / Linux / macOS 内核）、嵌入式设备、数据库都用 C 写
- 学会 C 之后，再学 C++、Java、Swift、Go 都会非常轻松，因为它们都"脱胎于" C

一句话：**C 是通往"懂计算机"之路的必修课**，即使以后不做底层开发，学 C 也会让你
写其他语言时心里更有底。

### 1.3 "编译"和"运行"是什么？

电脑 CPU 只认识**机器语言**（一堆 0 和 1），不认识 `printf("Hello")` 这种人类语言。
所以中间需要一个"翻译官"，把 C 代码翻译成机器语言，这个过程叫**编译**。

```
你写的 C 代码（人看的，.c 文件）
    ↓ 编译（编译器翻译成机器语言，Xcode 里自动完成）
机器语言程序（电脑看的，可执行文件）
    ↓ 运行（CPU 一条一条执行指令）
运行结果（屏幕上的输出）
```

| 名词 | 通俗解释 | 类比 |
|---|---|---|
| 源代码 | 你写出来的 C 代码文件（`.c`） | 菜谱文字 |
| 编译 | 把源代码翻译成机器能执行的文件 | 按菜谱把食材做成菜 |
| 运行 | 让电脑执行编译好的程序 | 把做好的菜端上桌吃 |
| 报错 | 编译器/程序发现有问题 | 菜谱写错导致做不出来 |

> 在 Xcode 里按 **Cmd + R**，就是"先编译、再运行"一步完成。
> 报错是电脑在说"这句我没看懂"或者"这里有矛盾"，**报错不可怕，可怕的是不看报错**。

## 二、学 C 需要准备什么？

| 需要 | 说明 | 备注 |
|---|---|---|
| 一台 Mac | macOS 系统 | 本课程所有截图以 macOS 为准 |
| Xcode | App Store 免费安装 | 苹果官方开发工具，自带 C 编译器 |
| 一颗敢动手的心 | 不怕报错、愿意敲代码 | 最重要的一项 |

不需要：
- ❌ 不需要先学数学（C 用到的最多是初中数学）
- ❌ 不需要英语很好（代码里用到的英文单词不超过 50 个，见术语表）
- ❌ 不需要背代码（写多了自然记住，查手册是正常操作）

> **正确学习法：先抄 → 再改 → 最后自己写。**
> 每一步都要真的在键盘上敲出来，不要只看不敲、只看不跑。

## 三、三个常见恐惧，一次破除

### 3.1 "我数学不好，能学编程吗？"

能。编程需要的主要是**逻辑拆分**能力，而不是数学天赋。
C 语言入门阶段只用得到：加减乘除、比较大小、计数。这些都是小学初中内容。
真正复杂的算法（比如矩阵运算）是以后的事，而且那时你也已经有经验了。

### 3.2 "我英语不好，能学吗？"

能。C 语言的关键字总共 32 个，例如 `int`、`if`、`while`、`return`，
都是很短的单词，看几天就眼熟了。遇到不认识的，随时翻本课程的**术语速查**。

常用的也就这些：
`int`（整数）、`char`（字符）、`printf`（打印输出）、`scanf`（读取输入）、
`if`（如果）、`else`（否则）、`while`（当…时）、`return`（返回）。

### 3.3 "我记不住怎么办？"

**没人能一次记住所有语法。** 记住 20% 的常用语法，就能写出 80% 的程序。
剩下的靠查。程序员每天都要查资料，这是工作常态，不是能力问题。
本课程给你准备了《C 术语速查》，就是专门用来"忘了就查"的。

## 四、怎么学才学得会？（本课程的方法）

本课程采用"七天学习法"，每天一个主题，节奏如下：

| 阶段 | 做法 | 目的 |
|---|---|---|
| 看 | 先读当天的讲解，看示例代码 | 建立概念 |
| 抄 | 把示例代码**手敲**进 Xcode 并运行 | 熟悉语法、练手感 |
| 改 | 改数字、改条件、改输出，看结果变化 | 理解每个部分的作用 |
| 写 | 不看答案，完成当天练习 | 真正学会 |
| 查 | 用术语速查和课后自查清单复习 | 巩固记忆 |

三个提醒：

1. **报错先自己读**。编译器会告诉你在第几行、什么错，先试着看懂再问。
2. **每天练 4～6 小时**，中间休息，比一次硬扛 10 小时效果好。
3. **卡住 30 分钟还过不去，再翻参考答案**，看完后关掉答案自己重写一遍。

## 五、今天的小任务（不写代码，但要动手）

1. 打开 Mac 的 App Store，搜索 **Xcode**，点击安装（下载较大，需要几分钟到几十分钟）。
2. 装好后打开 Xcode，随便点一点，找到"欢迎页"，确认它能正常启动。
3. 在本子上（或备忘录里）写下这 3 句话：
   - 编程 = 给电脑写一步一步的说明书
   - 编译 = 把 C 代码翻译成电脑能执行的语言
   - 学习方法 = 先抄、再改、最后自己写
4. 把本课的打卡清单全部勾上，然后进入第 1 天。

> 第 1 天你将亲手创建第一个 C 项目并运行 "Hello, C!"，那是你程序员生涯的第一步。
